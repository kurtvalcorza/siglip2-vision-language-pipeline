## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/siglip2_pipeline/` verbatim — four cells tagged `metadata.dimer.embedded_module`, one per module in dependency order (`config`, `model`, `provenance`, `pipeline`); the rewrites make the default weights directory working-directory-relative, replace the `resolve_weights_path` checkout-convenience line (the notebook passes `weights_dir` explicitly), and remove the package-relative `from .x import` lines whose names the preceding cells already define. Section 3 carries the model identity and the 9-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating commit, the four module paths, their combined SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when any carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` checks the manifest identity and hands the directory to the existing `verify_checkpoint`, which re-hashes every manifest entry, asserts the pinned `model.safetensors` digest and byte count, and refuses unsafe weight formats; `Siglip2Pipeline.from_pretrained(device="cpu", weights_dir=WEIGHTS_DIR)` loads the verified directory as an explicit path with `trust_remote_code=False` and `local_files_only=True`. The notebook's only external dependencies are the pinned PyPI distributions and the Hub at that revision.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/siglip2_vision_language_input_manifest.json` with the schema and ceilings (224×224 image contract, 64-token text maximum, prompt template), per-image observations, the texts, verdict, and one recorded rejection finding (a remote URL); `evaluation_report` (EVAL21) writes `outputs/siglip2_vision_language_evaluation_report.json` — `sample-sanity` with `top1_accuracy` (against the fixed-class baseline) and `recall_at_1` on the synthetic set, `not-measurable` (with what labelled data would make the task measurable) for BYOD without labels; embeddings and similarity are reported as representations with no intrinsic metric.
- The default sample is the repository's three deterministic synthetic PPM images regenerated in code and digest-asserted against `examples/sample-data/SHA256SUMS` (no download); the sanity metrics are evidence for the input contract and the five inference paths, not a correctness or benchmark claim.
- Vision-language obligations (Notebook Specification §20.8): sigmoid/similarity scores are distinguished from calibrated probabilities, prompt/label dependence is stated, a real BYOD image path exists, every capability exports machine-readable results, and the unsupported tasks (object detection, semantic segmentation, OCR, caption generation) are named.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.

## Learning contract

The release-grade tutorial exercises the repository's public `siglip2_pipeline`
API against the one immutable `google/siglip2-base-patch16-224` checkpoint.
It performs pretrained inference only: no gradient training, fine-tuning,
in-context conditioning, or fitted preprocessing state occurs.

The frozen release-reference environment installs the official CPU-only PyTorch
wheel, so the notebook intentionally executes on CPU even when a GPU is present.
GPU execution requires a separately pinned and tested environment and is outside
this tutorial's validated release contract.

The default path uses deterministic synthetic images so the notebook remains
non-interactive and reproducible. BYOD is available as an explicitly gated
Colab upload or local Jupyter path.

## Release verification (repository-installing carrier, superseded)

The repository CI performs static notebook JSON/Python-cell validation on pull
requests. On `main`, the integration job installs the frozen Python 3.12 CPU
reference environment, exercises the real pinned checkpoint, executes the
tutorial top-to-bottom, and uploads the tutorial outputs.

A notebook revision is release-ready only after the corresponding `main`
integration execution succeeds. Pull-request static checks alone are not
execution evidence. **The runs recorded below executed the previous, repository-installing
notebook; the standalone notebook registered above has not been executed yet — see
`../docs/release-verification.md`.**

## Applicable SHOULD deviations

- **§20.8 real-image verification:** the default automated path intentionally
  uses deterministic synthetic images to avoid adding a network- and
  license-sensitive external image dependency to CI. The notebook provides a
  real BYOD path for user-supplied images, but CI does not claim real-domain
  qualitative or quantitative validation. Real-image evaluation remains a
  deployment-specific follow-up and the notebook explicitly limits its claims.
- **DAT3 sample license:** the generated PPM assets are repository-generated
  synthetic tutorial data; no external dataset license applies.
